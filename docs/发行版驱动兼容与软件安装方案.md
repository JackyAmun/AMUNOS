# AMUNOS 当前发行版兼容性与软件安装方案

## 当前发行版边界

当前发行版镜像采用 `A.img` 启动，默认包含文本用户态程序：`TCC`、`EDIT`、`DFLAT`、`SYSINFO`、`BEEP`、`NET`，以及 libc、头文件、链接库和示例源码。GUI 演示程序和 WRITE 暂不进入发行镜像；GUI 源码和构建材料保留在仓库及 GUI 备份中，但当前内核和 libc 不再启用 GUI syscall。

## 驱动与设备兼容性

设备访问统一经过带锁的块设备层和盘符挂载表。块设备记录扇区大小、容量、读写/可移除能力、介质代次及最后错误；文件系统不再需要根据设备编号猜测能力。单扇区接口保持兼容，并增加连续扇区读写入口。

| 设备 | 当前状态 | 文件系统/格式 | 主要限制 |
|---|---|---|---|
| IDE ATA 主从盘 | 可读写 | FAT12/FAT16，FAT32 路径已存在 | PIO 轮询；MBR 主/逻辑分区可独立挂载 |
| AHCI SATA | 只读 | 主要用于读取 FAT 卷 | 只选择首个 SATA 端口；可扫描 MBR/EBR；无写入、热插拔和完整端口管理 |
| ATAPI 光驱 | 只读 | ISO9660 | 扫描传统 IDE 两通道主从位置；有介质检测、REQUEST SENSE、容量读取和重试；不支持 MMC 刻录 |
| 软盘 FDC | 可读写 | FAT12；1.44MB/1.2MB/720KB/360KB | 仅驱动器 0；读取使用 PIO，写入使用 8237 DMA 通道 2；暂无线程睡眠和 IRQ 驱动队列 |
| MBR 磁盘 | IDE 可读写，AHCI 只读 | FAT12/FAT16/FAT32 | 支持四个主分区和最多 16 个 EBR 逻辑分区；最多 25 个虚拟卷槽；不支持 GPT |
| RTL8139 网卡 | 原始帧轮询收发 | Ethernet II | PCI bus 0 发现；暂不实现 ARP/IP/DHCP/TCP/UDP；适用于实验帧与后续协议栈底层 |
| PC speaker | PIT channel 2 音调输出 | 37..20000 Hz，1..5000 ms | `BEEP [Hz] [ms]` 用户态程序；轮询计时，单次调用互斥 |

因此，“设备格式兼容”目前只在块设备入口层统一。FAT12/16 是最稳定的可写目标，FAT32 属于受限支持，ISO9660 和 AHCI 主要承担只读数据来源。软盘可以写入，但容量小、易更换且当前只有轮询式恢复路径，不应作为大软件包的默认安装目标。光驱写入不能复用普通扇区写接口，需要独立实现 MMC 写命令、轨道/会话与介质封盘状态机。

## P0/P1/P2b 进度

- P0：统一设备能力、容量、介质状态和错误码；串行化块 I/O；为范围、只读、无介质和忙状态提供明确失败结果。
- P0：`DEVS` 按实际能力显示 `RW`/`RO`、`REM` 和无介质状态，避免安装器向只读设备写入。
- P1：FDC 支持常见 FAT 软盘几何、复位/校准/寻道重试、状态字错误映射以及 DMA 写入。
- P1：ATAPI 扫描四个传统 IDE 位置，使用 TEST UNIT READY、REQUEST SENSE 和 READ CAPACITY 管理介质变化。
- P2a：识别直接 FAT 卷或 MBR，文件系统 LBA 以分区起始位置为基准。
- P2b：枚举 MBR 主分区与有界 EBR 链，为卷建立虚拟块设备槽并自动分配盘符；IDE 虚拟卷保持写入能力，AHCI 虚拟卷只读。
- P2b：RTL8139 轮询原始帧收发与 PC speaker 定频发声 syscall/`BEEP` 示例程序。
- 后续：GPT、AHCI IDENTIFY 的真实容量与写入、IRQ/等待队列、缓存刷新和热插拔事件、网络协议栈。

## 目前需要保留的限制

1. 盘符由自动挂载顺序分配，引导盘优先为 `A:`，缺盘时后续盘符会前移。
2. `CMDS.BIN` 保存命令到 ELF 的映射，并由内核保护，避免普通删除和覆盖误伤启动命令。
3. 8.3 文件名仍是默认兼容格式。长文件名、完整 Unicode 文件名和分区 UUID 还没有成为稳定接口。
4. AHCI 仍为只读；ATAPI 光驱仅支持读取。FDC 虽已可写，安装器仍应提示容量和可移除介质风险。

## 未来软件安装逻辑

### 第一阶段：可用的文本安装器

先把安装流程做成内置命令，使用当前文件系统能力：

```text
PKG LIST
PKG INFO name
PKG INSTALL A:/PKG/NAME.PKG
PKG REMOVE NAME
PKG VERIFY NAME
```

软件包暂定使用一个简单的目录格式：包头、包名、版本、目标目录、文件数量、总大小和校验值，后面跟文件表和文件数据。第一版只允许安装到 `A:/BIN`、`A:/USR/LIB`、`A:/USR/INCLUDE` 和 `A:/USR/SRC`。

安装步骤应为：读取包头并检查大小 → 检查目标盘可写和剩余空间 → 解包到临时目录 → 校验每个文件 → 更新 `CMDS.BIN` → 写入安装记录。任何一步失败都保留旧文件和旧命令表。

### 第二阶段：仓库盘与恢复

把 `B:` 或 `C:` 作为软件仓库盘，系统盘 `A:` 只保留启动文件和基础工具。安装器从仓库目录读取索引，索引记录包名、版本、架构、依赖和校验值。升级时先写入新文件，再切换命令映射；删除时检查依赖，并把旧版本移入恢复目录。

### 第三阶段：驱动感知安装

安装器读取设备能力表，只把可写 FAT12/16/32 卷列为安装目标；对 AHCI、ATAPI 显示只读状态，对软盘显示可移除和容量警告。未来加入分区层后，再把盘符绑定到卷 UUID，避免设备顺序变化导致路径改变。

### 第四阶段：未来可选的图形前端

如果未来重新引入图形层，安装器可以复用 DFLAT 的列表框、进度条、消息框和文件选择器，但安装核心仍由文本 `PKG` 命令提供。这样图形前端退出或损坏时，系统仍能从 shell 完成安装、卸载和修复。

## GUI 备份

当前 GUI 源码和构建配置已保存到 `backups/gui-v0.5-20261004.zip`，同时保留 `gui.c`、`gui/` 和 WRITE 源码。恢复 GUI 时，应先恢复构建目标和镜像文件列表，再恢复 `CMDS.BIN` 中的 `GUI`、`WRITE` 映射。
