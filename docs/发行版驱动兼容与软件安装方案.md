# AMUNOS 当前发行版兼容性与软件安装方案

## 当前发行版边界

当前发行版镜像采用 `A.img` 启动，默认包含文本用户态程序：`TCC`、`EDIT`、`DFLAT`、`SYSINFO`，以及 libc、头文件、链接库和示例源码。GUI 演示程序和 WRITE 暂不进入发行镜像；GUI 源码和构建材料保留在仓库及 GUI 备份中，但当前内核和 libc 不再启用 GUI syscall。

## 驱动与设备兼容性

设备访问已经统一经过 `blk_read` / `blk_write` 和盘符挂载表，但不同设备的读写能力与文件系统格式并不相同。

| 设备 | 当前状态 | 文件系统/格式 | 主要限制 |
|---|---|---|---|
| IDE ATA 主从盘 | 可读写 | FAT12/FAT16，FAT32 路径已存在 | PIO 轮询；无分区表解析；整盘按一个卷处理 |
| AHCI SATA | 只读 | 主要用于读取 FAT 卷 | 只选择首个 SATA 端口；无写入、热插拔和完整端口管理 |
| ATAPI 光驱 | 只读 | ISO9660 | 当前按 QEMU IDE1 从盘探测；不支持写盘和完整 ISO 扩展 |
| 软盘 FDC | 只读 | 1.44MB FAT12 | 仅驱动器 0；非 DMA 轮询；介质更换和写盘尚未完成 |
| 分区盘 | 部分可读 | 无统一分区层 | 目前没有 MBR/GPT 解析，整盘必须直接表现为可识别卷 |

因此，“设备格式兼容”目前只在块设备入口层统一。FAT12/16 是最稳定的可写目标，FAT32 属于受限支持，ISO9660、AHCI 和软盘主要承担只读数据来源。安装软件时应默认安装到可写 FAT 盘，不能把光驱或 AHCI 盘当作安装目标。

## 目前需要保留的限制

1. 盘符由自动挂载顺序分配，引导盘优先为 `A:`，缺盘时后续盘符会前移。
2. `CMDS.BIN` 保存命令到 ELF 的映射，并由内核保护，避免普通删除和覆盖误伤启动命令。
3. 8.3 文件名仍是默认兼容格式。长文件名、完整 Unicode 文件名和分区 UUID 还没有成为稳定接口。
4. AHCI、ATAPI、FDC 的写入能力需要先补齐错误恢复、缓存刷新和介质状态检查，之后才能作为软件安装盘。

## 未来软件安装逻辑

### 第一阶段：可用的文本安装器

先把安装流程做成内置命令，使用当前文件系统能力：

```text
PKG LIST
PKG INFO name
PKG INSTALL A:/PKG/NAME.PKG
PKG REMOVE NAME
PKG VERIFY NAME
```

软件包暂定使用一个简单的目录格式：包头、包名、版本、目标目录、文件数量、总大小和校验值，后面跟文件表和文件数据。第一版只允许安装到 `A:/BIN`、`A:/USR/LIB`、`A:/USR/INCLUDE` 和 `A:/USR/SRC`。

安装步骤应为：读取包头并检查大小 → 检查目标盘可写和剩余空间 → 解包到临时目录 → 校验每个文件 → 更新 `CMDS.BIN` → 写入安装记录。任何一步失败都保留旧文件和旧命令表。

### 第二阶段：仓库盘与恢复

把 `B:` 或 `C:` 作为软件仓库盘，系统盘 `A:` 只保留启动文件和基础工具。安装器从仓库目录读取索引，索引记录包名、版本、架构、依赖和校验值。升级时先写入新文件，再切换命令映射；删除时检查依赖，并把旧版本移入恢复目录。

### 第三阶段：驱动感知安装

安装器读取设备能力表，只把可写 FAT12/16/32 卷列为安装目标；对 AHCI、ATAPI 和软盘显示只读状态。未来加入分区层后，再把盘符绑定到卷 UUID，避免设备顺序变化导致路径改变。

### 第四阶段：未来可选的图形前端

如果未来重新引入图形层，安装器可以复用 DFLAT 的列表框、进度条、消息框和文件选择器，但安装核心仍由文本 `PKG` 命令提供。这样图形前端退出或损坏时，系统仍能从 shell 完成安装、卸载和修复。

## GUI 备份

当前 GUI 源码和构建配置已保存到 `backups/gui-v0.5-20261004.zip`，同时保留 `gui.c`、`gui/` 和 WRITE 源码。恢复 GUI 时，应先恢复构建目标和镜像文件列表，再恢复 `CMDS.BIN` 中的 `GUI`、`WRITE` 映射。
