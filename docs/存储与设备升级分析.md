# AMUNOS 存储与设备升级分析

> 目标：从"IDE 硬盘 + INT13h 引导 + FAT12/16 硬编码"升级为
> **软盘/硬盘通用引导 · 设备自动发现（IDE/AHCI/NVMe/软驱）· 自动挂载 · FAT32 · 网络**。
> 本文是现状分析 + 分阶段方案（2026-08-30），配套流程规范见
> 《AMUNOS_开发流程与协作规范.md》。

---

## 1. 现状事实清单（含证据行号）

### 1.1 引导链（boot.asm）

- 引导扇区手工构造 FAT12 BPB：`boot.asm:21-45`，rsvd=193（1 boot + 192 内核 = 96KB 上限），
  几何按 1.44MB 软盘声明（SPT=18/HPC=2/2880 扇），但 `bpb_drive_num=0x80`（line 40）——
  **内容是软盘镜像，却按硬盘挂载**。
- 内核加载 = 双段 INT 13h：第 1 段 AH=02h CHS 读 128 扇→0x08000（line 64-74，
  **DL 硬编码 0x80**，line 70）；第 2 段 AH=42h 扩展 LBA 读 64 扇→0x18000（line 76-85，
  DAP 在 0x7E00）。SeaBIOS 单次 AH=02h 读 192 扇实测 Disk Error，故拆段。
- 无 AH=41h 扩展支持检测、无重试、错误只打 "Disk Error!" 死循环（line 88-92）。
- A20 经 0x92；VBE 0x111（640×480×16）参数写 0x1500 传内核。

### 1.2 内核态磁盘访问（disk_io.asm）

- **32 位保护模式下 IDE ATA PIO 端口直访**（0x1F0 主通道 / 0x170 次通道），不调 BIOS、
  无 IRQ、无 DMA。`read_sector_asm(lba,buf,drive_idx)`：bit1 选通道、bit0 选主/从，
  **每次 1 扇区**，LBA28（≤128GB），命令 0x20/0x30。
- 忙等 `DISK_TIMEOUT=0x100000` 空转；**无 ERR 清除、无软复位（0x3F6）、无重试**。
- 隐含驱动器映射：0=A(主通道主) 1=B(主通道从) 2=C(次通道主) 3=D(次通道从)。

### 1.3 文件系统（fs.c）

- FAT12/16 双支持：读扇 0 解 BPB（扇大小硬编码 512），FAT 位宽按簇数 ≤4084 判定
  （`fs.c:70-75`）。**无 FAT32 分支**（EOC 表只有 0xFF8/0xFFF8/0xFFF/0xFFFF 四值，
  无 root_cluster/FSInfo/0x0FFFFFFF）。
- FAT 缓存：固定物理地址 0x70000、96KB 上限，**全盘单份全局**，换盘时整个 `fs_init()`
  重载（`fs_drive_enter/restore`）。**缓存超出 96KB 的盘：FAT 条目读写会越界或读到垃圾**
  （`fat_get_entry` 无边界检查，`fs.c:165-175`）。
- 无挂载表：只有全局 `current_drive_idx`（kernel.c:3，写死 0）+ 约定 0..3=A..D；
  `fs_drive_present` 逐盘试探读扇 0 验签。**无 MBR/GPT 分区解析**，整盘即 FAT 卷。
- 写路径：文件 ≤256 簇（128KB 上限）；`fs_write_file_in_dir` 是**删除+重建**，中途失败
  无回滚（旧数据已毁）。
- LFN：`fs_list_dir` 跳过 attr==0x0F 条目（fs.c:672）——长文件名只能按 8.3 别名访问。

### 1.4 启动流程与枚举

- `kmain()`：`fs_init()` 只对 current_drive_idx=0 初始化**一次**，无任何盘枚举/探测；
  字库从 **C:HZK16** 载入（kernel.c:86，又一个硬编码盘符）。
- 全仓库 **无 PCI 枚举、无 AHCI/NVMe/软驱控制器(0x3F0)/ATAPI/网卡代码**
  （grep 证据见调研记录）。
- Makefile 全部 `-hda/-hdb/-hdc`，从不 `-fda`，无 `-boot` 参数。

### 1.5 结论

当前栈 = **"BIOS 引导 + IDE PIO + 约定式盘符"** 三层都不可扩展：
引导假设 0x80 硬盘；内核只有 IDE PIO 一条路径；文件层没有设备抽象层。

## 2. 升级方案（分四阶段，可独立交付）

### 阶段 A：引导介质通用化（软盘支持）—— 最小改动，最先做

1. **引导扇区感知真实 DL**：BIOS 传入的 DL 寄存器保存下来替代硬编码 0x80
   （boot.asm:70），并写入 BPB `bpb_drive_num`，传给内核（如复用 0x1500 参数区）。
2. **CHS/LBA 双路径**（参考 kernel-master `boot/boot.asm` L152-166 DAP 定义、L448 起
   `LBA_READ`）：INT 13h AH=41h 检测扩展支持 → 有则全 LBA（第 1 段也改 AH=42h），
   无则回退 CHS 并按 BPB SPT/HPC 换算。软盘（DL<0x80）天然走 CHS。
3. **1.44MB 软盘装载适配**：软盘只有 2880 扇，rsvd=193 占掉 96KB 后数据区仅剩
  ~1.2MB——A.img 内容本就是软盘几何，只需 Makefile 增加软盘运行目标：
   ```
   run-floppy: qemu-system-i386 -fda A.img -boot a ...
   ```
   引导扇区 DL=0x00 后双段读逻辑不变（AH=02h 软盘 CHS 同样可用）。
4. 校验两个内核加载段的"Disk Error"路径：加重试 3 次 + 打印 AH 错误码。

### 阶段 B：设备自动发现 + 自动挂载（核心结构改造）

新增 **块设备抽象层**（借 kernel-master 的 request-header 思想，做 32 位简化版）：

```c
typedef struct {
    const char *name;          /* "ide0-master" / "ahci0-port1" / "nvme0n1" / "fd0" */
    int  (*read)(u32 lba, void *buf, u32 nsec);
    int  (*write)(u32 lba, const void *buf, u32 nsec);
    u32  capacity_lba;
    u32  sector_size;          /* 512 或 4096(NVMe 可按 512 逻辑扇暴露) */
} blkdev_ops_t;
```

自动发现顺序（内核启动时 `bus_scan()`）：

| 总线 | 探测方式 | 关键点 |
|------|----------|--------|
| PCI 枚举 | conf1 机制：0xCF8/0xCFC，扫 bus 0..dev 31..fun 7，读 class/subclass | SATA(AHCI)=class 01h/06h/01h，IDE(兼容)=01h/01h，NVMe=01h/08h/02h，网卡=02h/00h |
| IDE ATA | 现有 PIO 路径 + **IDENTIFY DEVICE (0xEC)**：读型号/扇区数/LBA 支持 | 保留现 disk_io.asm 为后端之一，补 ERR 处理与 0x3F6 软复位 |
| AHCI (SATA) | PCI 挂上后的 ABAR（BAR5）映射，GHC.CAP，逐 port 检测 device present，FIS 完成 | 建议先做只读，DMA 命令表放内核堆 |
| NVMe | PCI BAR0 映射 CAP/doorbell，admin queue（识别/读），IOCQ/IOSQ | 工作量最大，建议放最后或放用户态路线 |
| 软盘 | 不做 0x3F0 控制器编程；引导时 DL<0x80 → 注册 BIOS INT13h 后端**不可行**（保护模式），改为：内核提供 fd0 = 仅引导盘信息（几何来自 BPB），或实现 0x3F0/FDC PIO 驱动（PS/2 鼠标同级的端口驱动工作量） | FDC 驱动单独评估 |

自动挂载（**建挂载表，替代约定式盘符**——借 DOS CDS→DPB 分层）：

```c
typedef struct {
    u8  used, flags;           /* 本地/无介质 */
    u8  fstype;                /* FS_FAT12/16/32 */
    blkdev_ops_t *dev;
    u32 part_lba_off;          /* 分区起始 LBA（MBR 支持） */
    BPB_t bpb;                 /* 解析后的卷参数 */
} mount_t;                     /* mount[8]，盘符 = 'A'+idx 动态分配 */
```

- `bus_scan()` 逐设备 `try_mount()`：读 LBA0 验 0x55AA → 若是 MBR（分区表签名）
  解析 4 个主分区逐个试 FAT → 否则整盘按 FAT 解析；成功即占一个盘符。
- 引导盘（BIOS DL 记录的那个）恒为 A:；其余按发现顺序 B:, C:, ...
- `fs_init()` 改为 per-mount（解除"全盘单份 FAT 缓存 + 换盘整体重载"结构），
  FAT 缓存改为 per-mount 小缓存（或 LRU 块缓存，参考 kernel-master `blockio.c`）。
- `fs_drive_present`/`parse_drive`/CMDS.BIN 搜索全部改走 mount 表。

### 阶段 C：FAT32 支持

按 kernel-master `fatfs.c` 的 `ISFAT32(dpbp)` 分支模式移植**纯算法**（16 位→32 位无碍）：

1. BPB：`total16==0` 取 total32；`root_entries==0` 且 `spf16==0` → FAT32 判定
   （比簇数推断更可靠，三种 FAT 统一判据）；取 bpb+44 `root_cluster`。
2. FAT 表：EOC 三档 + 0x0FFFFFF7 坏簇；FAT12 的 12 位跨字节读改写可参考
   `fattab.c`（我们已实现，保持）。
3. 根目录：FAT32 根 = `root_cluster` 起始的簇链（不再有固定根目录扇区）——
   `fs_dir_lba`/根目录遍历需按"目录即簇链"统一重写（顺带解除 256 扇区目录上限）。
4. FSInfo 可先不实现（只读不依赖；写入时 free count 可填 -1，多数驱动容忍）。
5. mkfat16.py → mkfat.py 增加 FAT32 镜像生成，回归脚本加 FAT32 用例。
6. LFN 长文件名（可选同阶段）：读路径解析 attr==0x0F 的 LFN 序列拼 UTF-16→UTF-8；
   写路径可后置。kernel-master `fatfs.c:299-320`（remove_lfn_entries）是蓝本。

### 阶段 D：网络（新子系统，建议独立分支）

- 网卡驱动先做 **QEMU 默认virtio-net 或 rtl8139**（QEMU `-device rtl8139`）：
  PCI 枚举（阶段 B 复用）→ IO BAR 或 MMIO → Tx/Rx 描述符环。
- 协议栈最小集（内核态或用户态均可，建议内核态小栈）：
  `ARP → IPv4 → ICMP(echo) → UDP`，再 `DHCP`（UDP 67/68）拿 IP；
  TCP 可用 lwIP 级裁剪或自写简化版（工作量大，放最后）。
- 参考：xv6-public 的 e1000 驱动、osdev wiki rtl8139 样例（kernel-master 无网络实现）。
- 里程碑：`PING <ip>` shell 命令（ARP+ICMP 回显）→ `TFTP` 拉文件 → 再谈 TCP。

## 4. 建议实施顺序

```
1. B3 磁盘锁 + B2 返回值检查（止血，半天级）
2. 阶段 A：DL 感知 + CHS/LBA 双路径 + -fda 软盘启动（Makefile + boot.asm）
3. 阶段 B：PCI 枚举 + blkdev 抽象 + mount 表 + IDENTIFY 自动发现（IDE 先行）
   → AHCI 只读 → FAT32（阶段 C）
4. 阶段 D 网络：rtl8139 + ARP/ICMP(PING) → DHCP → UDP/TFTP
```

约束提醒：内核 96KB 上限已临界——**阶段 B 动工前先决定扩容方案**
（boot 第 2 段仍有余量可到 128KB+，需改 rsvd 与 AH=42h 段数；或驱动放 0x100000
独立加载段）。每阶段保持 validate_* 全绿 + 新增对应回归用例。
